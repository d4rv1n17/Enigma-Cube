# Обновления приложения

Канал выпусков: [d4rv1n17/Enigma-Cube](https://github.com/d4rv1n17/Enigma-Cube/releases).
Токены и учётная запись GitHub пользователю не нужны.

## Поведение в установленной Windows-версии

1. Автоматическая проверка включена по умолчанию. Проверки выполняются в фоне
   с интервалом 12 часов; после старта приложения проверяется, пора ли обновить
   сведения. Без подключения таймер и обучение продолжают работать.
2. Рассматривается только стабильный опубликованный релиз с версией больше
   текущей. Числа сравниваются как версии: 3.10 новее 3.9; 3.1 и 3.1.0 равны.
3. Загружается только `EnigmaCube-Setup-<version>.exe` из этого репозитория.
   Используются HTTPS и SHA-256 из метаданных GitHub Release Asset. Размер
   ограничен; незавершённый файл имеет расширение `.part`.
4. После проверки появляется предложение «Перезапустить и обновить».
   Установка не начинается автоматически во время сборки. Перед перезапуском
   данные сохраняются; активная сборка в основном или мини-таймере блокирует
   установку.
5. Отдельный скрытый процесс ждёт завершения приложения, ещё раз проверяет
   SHA-256 и запускает установщик в режиме обновления. После установки открывает
   приложение. Результат сохраняется для диагностики неудачной установки.
6. Новые файлы сначала распаковываются отдельно. Ошибка распаковки не затрагивает
   текущую версию. При ошибке замены восстанавливаются прежние файлы и манифест;
   если восстановление само заблокировано ОС, резервные оригиналы сохраняются.
   Пользовательские файлы вне манифеста установки не удаляются.

Переключатель автоматической проверки/загрузки, ручная проверка и кнопка установки
находятся в «Настройки → Интерфейс → Обновления». Если автоматическая загрузка
отключена, доступный выпуск можно загрузить отдельной кнопкой.

Запуск из исходников позволяет проверить наличие релиза, но не заменяет файлы
проекта установщиком. Автоматическая установка доступна в Windows-сборке.

## Публикация следующей версии

Существующий workflow `.github/workflows/build-windows.yml` собирает установщик
и прикрепляет его к GitHub Release. Для следующего выпуска необходимо увеличить
`enigma_timer.VERSION` и опубликовать соответствующий релиз, например `v3.2`.
Имя файла должно соответствовать версии. GitHub предоставляет digest загруженного
asset; клиент отказывается от загрузки неподтверждённого файла.

Автообновление впервые включено в версию 3.2. Для перехода с 3.1 необходимо один
раз скачать и запустить установщик 3.2; последующие выпуски приложение проверяет
самостоятельно. Проверки загрузки и отката используют тестовые пакеты и не
заменяют установленный выпуск пользователя.

Начиная с 3.2.1 установщик проверяет выбранную папку по наличию
`EnigmaCube.exe`, даже если запись установки в реестре утрачена. При смене пути
режим «Установить / Обновить» пересчитывается сразу. Выбирай папку, где уже лежит
программа; установщик заменит её файлы, сохранив данные в `%APPDATA%\EnigmaTimer`.
Метаданные и команды удаления другой установки не используются для нового пути.

Реализация: `enigma_timer/updates.py`; интеграция окна и настроек — `window.py`
и `dialogs.py`; режим установки без принудительного завершения других процессов —
`installer/setup_app.py --quiet --update --dir <existing install>`.
